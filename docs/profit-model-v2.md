# 盈利模型 V2：可成交净优势模型

## 结论

H1–H8 已经说明，单纯更换指标、窗口或持有期不能解决系统性亏损。本轮将盈利模型从“信号出现就交易”改为“预测的可成交净优势足够大才允许交易”。这是一套研究决策内核，不是已证明盈利的策略，也不包含真钱下单。

## 模型结构

每个候选交易必须提供：

- `expectedPriceEdgeBps`：方向调整后的预期价格收益，必须是可成交价格到可成交价格；
- `forecastStandardErrorBps`：预测误差，用于保守下界；
- `expectedFundingBps`：按多空方向计入后的预期资金费收益，付费为负；
- `fundingStressBps`：资金费不确定性压力扣减；
- `forecastTime`、`bookTime`：输入时间戳；
- `quantity`、`side`、`symbol`：实际候选订单，而不是抽象百分比。

核心计算为：

```text
expectedGross = expectedPriceEdge + expectedFunding
expectedNet = expectedGross - executionCost
conservativeNet = expectedNet
                  - confidenceZ × forecastStandardError
                  - fundingStress
```

其中 `executionCost` 包括：

1. 当前盘口逐档走价的入场和出场成本；
2. 双边手续费；
3. 盘口成本压力倍数；
4. 每腿的冲击缓冲和延迟缓冲。

只有同时满足以下条件才会返回 `TRADE`：

- 数据时间戳没有未来函数；
- 预测和盘口未过期；
- 入场及退出数量都能在可见盘口中成交；
- 订单占可见盘口比例不超过冻结上限；
- 价格预期为正；
- 毛优势/执行成本达到冻结覆盖倍数；
- 保守净优势达到最低门槛。

任意条件失败都返回 `NO_TRADE`，并保留全部失败原因。沉默地降低门槛、改用中间价或忽略深度不足都属于系统错误。

## 组合和仓位

仓位先按止损距离和账户风险预算计算，再按交易所数量步长向下取整；低于最小名义价值时拒绝交易。组合门控同时限制：

- 总毛杠杆；
- 净方向暴露；
- Beta 暴露；
- 单币种名义金额；
- 同一事件簇的止损损失；
- 组合总止损损失；
- 同时持仓数量。

`config/net-edge-model.json` 中的数值只是可审计的研究默认值，不是针对用户账户的杠杆或风险建议。没有账户净值、合约过滤器、实际佣金等级和实时盘口时，系统不得生成可执行订单。

## 新的盈利模型方向

第一候选模型不再使用K线成交量或影线作为强平代理，而是研究“真实强平流 + 盘口恢复”的短持仓事件：

1. 用 `forceOrder` 记录强平方向和名义金额；
2. 用逐笔聚合成交和本地盘口记录冲击后的主动成交、价差和深度恢复；
3. 只有当预测的后续价格优势覆盖双边压力成本时才生成候选；
4. 使用预先冻结的固定持有上限和止损规则；
5. 将每次未交易也登记为 `NO_TRADE`，避免只保存赢家。

这只是待验证假设。H1 曾使用成交量、主动成交和影线作为代理，因此真实 `forceOrder` 和本地盘口数据必须单独登记；不能把新数据采集后产生的正结果追溯包装成历史样本外证据。

## 验证顺序

1. 先连续封存公开市场流，至少覆盖30天暖机期；期间不读取结果调参数。
2. 冻结事件定义、时间延迟、费用、盘口冲击、持有上限和淘汰条件，登记为新的实验ID。
3. 先做数据质量和可成交性验证：序列断裂、盘口更新缺口、强平事件时间异常或交易所规则缺失即拒绝计算PnL。
4. 再做D0开发检验：毛优势、成本覆盖、方向/币种/月份/市场状态、最佳事件簇剔除和安慰剂。
5. 只有冻结后实时产生的数据才进入F0；至少同时达到180天和100笔已关闭交易后才允许晋级审查。

在完成F0前，任何D0正收益都只能说明“值得继续观察”，不能说明具备实盘价值。
