# 不可覆盖实验登记规则

## 1. 能力边界

普通本地文件系统无法实现绝对“不可篡改”。本项目采用三层控制：

1. 不可覆盖的实验工件；
2. SHA-256 前向哈希链，令修改可被发现；
3. Git 受保护分支、签名提交和外部 WORM 锚定（建立远程仓库后执行）。

在第 3 层启用前，准确术语是“可验证的防篡改登记”，不能声称管理员无法重写历史。

## 2. 必登记事件

每个正常完成的实验按顺序登记：

```text
preregistered → data_locked → completed | failed
```

若下载、数据校验或执行准备在 `data_locked` 前失败，可以直接登记：

```text
preregistered → failed
```

- `preregistered`：假设、固定参数、数据范围、成交模型、成本和淘汰条件；
- `data_locked`：实际文件清单和 SHA-256；
- `completed`：结果摘要、逐笔文件和结论；
- `failed`：下载失败、代码失败、无信号或人工停止，同样必须保存原因；失败发生在哪一阶段，就记录当时已经存在的日志和清单。

在 `data_locked` 前可以追加 `amended` 事件，但不能覆盖原预注册。数据锁定后禁止修改信号、参数、成本或淘汰门槛；任何修改使用新实验 ID。

## 3. 哈希链

`registry/ledger.jsonl` 每行包含：

- 单调递增 `sequence`；
- UTC `recorded_at`；
- `experiment_id` 和 `event_type`；
- 工件相对路径和工件 SHA-256；
- 前一事件哈希 `previous_hash`；
- 当前事件规范化 JSON 的 SHA-256 `hash`。

验证命令：

```powershell
npm.cmd run registry:verify
```

验证失败时不得运行新实验、发布结果或启动前向计时。

## 4. 文件规则

- 工件路径一旦进入登记链不得修改或删除；
- 修正使用新文件和新事件；
- 参数组合即实验；批量网格必须保存网格中每个组合的结果，不能只保存赢家；
- 失败结果的保留期与成功结果相同；
- 逐笔交易、汇总、日志和代码提交必须可以相互追溯；
- 所有时间使用 UTC 存储，同时保存显示时区；
- 实验 ID 格式为 `HY-EXP-NNNN`。

## 5. 远程仓库启用后的强制项

- `main` 禁止强推和删除；
- 登记文件变更必须通过 PR；
- CI 必须运行登记校验和测试；
- 合并提交或发布标签必须签名；
- 每日把最新链头哈希写入独立 WORM 存储；
- 数据库登记表只允许追加，禁止 `UPDATE` 和 `DELETE`，由触发器校验前一哈希；
- 管理员例外操作也必须进入独立审计日志。
