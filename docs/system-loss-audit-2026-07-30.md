# 合约交易系统亏损风险审计

审计日期：2026-07-30  
审计对象：旧项目公开代码与在线影子盘、衡域研究代码、实验登记链、HY-EXP-0001 数据与结果  
结论边界：本报告覆盖当前可访问的代码、公开行情数据和只读在线状态；没有币安账户、订单回报、逐档盘口、V15 私有代码或 Supabase 原始表权限，因此不能声称穷尽账户侧和未提供代码中的全部风险。

## 1. 总结

当前没有证据支持真钱交易。已经确认的核心问题不是仓位太小、参数不够精细或交易次数不足，而是：

1. 旧影子策略已经出现显著负期望；
2. 新项目首个独立机制在未计成本前也亏损，说明成本不是唯一原因；
3. 现有研究回放不是账户级模拟，不能给出可部署的杠杆、保证金、清算或最大回撤；
4. K 线开盘价并不是可执行买一/卖一价，固定滑点无法覆盖点差、深度、延迟、部分成交和拒单；
5. 当前统计把相关交易当作独立样本，容易高估显著性；
6. 历史币种集合和数据完整性检查仍不足以排除幸存者偏差、退市遗漏和归档损坏；
7. 实验登记链原先存在可被脚本意外重写及状态机未重放的缺陷。本轮已修复，但本地哈希链仍不等于外部不可篡改存证。

因此，旧策略继续判定为“未证明有效”，HY-EXP-0001 判定为“固定规格淘汰”。下一步只能检验一个预先冻结、机制不同的新假设，不能调优这两个失败规则。

H5 在157个不重叠 BTC 冲击中产生54个满足分散度和容量要求的组合事件。冻结的反应残差收敛方向在未计成本前已经亏损：毛收益单位 -0.06076，平均每事件 -11.25 bps。基准净收益单位 -0.12551、PF 0.266；压力净收益单位 -0.19032、PF 0.134；去最佳5个事件仍亏 -0.21745。

### 2.7 HY-EXP-0010

H6 双周资金费率携带实验在62个固定候选时点中只产生13个满足24 bp预测携带门槛与容量约束的组合。压力净收益单位+0.12510、PF 1.981，极端成本及延迟5分钟仍为正；实际资金费扣压力执行成本后为+0.00470，说明资金费持续性存在一定信息，但只有约3.61 bps/入选期的成本后安全垫。

该正收益没有通过稳健性门槛：最佳5期合计贡献全部净收益的148.0%，删除后亏损-0.06000；低资金费多头侧亏损-0.02364；ETH单币贡献压力总净收益的100.3%，删除ETH后为-0.00038。滑点后价格损益贡献总净收益的81.7%，结果主要依赖高费率空头侧的相对价格表现，而不是稳定、对称的资金费现金流。固定H6规格淘汰；不得事后降低24 bp门槛、只保留空头侧或排除亏损币种。

### 2.8 HY-EXP-0011

H7 固定四组跨资产相对价值实验共执行18笔交易。压力净收益单位+0.02958、PF 1.370，极端成本与额外5分钟延迟后仍盈利，3/4配对及两个残差方向盈利，表面上比前几轮更接近正期望。

但该结果不具备稳健性：只有1/18交易真正穿越入场时冻结的90天中心，其余17笔均在7天上限退出；最佳5笔贡献全部压力净收益的293.2%，删除后亏损-0.05716。交易数不足40，最大正收益月份贡献40.66%也超过冻结上限。固定H7规格淘汰；不能把持有期内的部分相对价格移动包装为已经证明的均值回归，也不得事后延长7天上限、删除ETH/ETC或更换配对。

### 2.9 HY-EXP-0012

H8 固定周频横截面残差动量实验产生116个预定组合，其中98个通过数据和容量规则。毛价格收益平均约+8.85 bps/组合，但基础情景已经亏损-0.02183；压力净收益单位-0.13936、PF 0.879、最大回撤-0.53510，极端成本和额外5分钟延迟也均亏损。

微弱毛优势无法覆盖换手成本，而且缺乏跨状态稳定性：2024年11月贡献+0.36256，排除该月后为-0.50193；BTC事前上涨状态盈利+0.31084、下跌状态亏损-0.45021；多头腿亏损-0.05699，BTC对冲腿亏损-0.10602。最佳5周合计+0.44327，删除后为-0.58263。固定H8规格淘汰；不得事后只保留BTC上涨状态、删除对冲腿、降低容量门槛或改动窗口来包装结果。

## 3. 风险清单

### P0：足以使盈利结论失效或造成不可控实盘亏损

| 问题 | 亏损路径 | 当前证据 | 处置 |
|---|---|---|---|
| 信号无正期望 | 每笔毛收益为负，交易越多亏损越多 | 旧影子 PF 0.145；H1 毛收益为负 | 旧规则和 H1 均淘汰 |
| 所有截至边界的数据已暴露 | 反复查看同一历史会把噪声包装成优势 | V1–V15 与 2026-07-30 前数据均已查看 | 只允许 D0 淘汰；前向从边界后重新计时 |
| 无账户级保证金与清算引擎 | 杠杆、维持保证金、标记价格、强平和 ADL 可使回测盈利但账户破产 | H1 只报告等名义收益单位 | 禁止把其回撤解释为账户回撤 |
| 双腿订单不是原子成交 | 一腿成交、另一腿延迟或拒单会把小额价差交易变成裸方向仓位 | H4 同步压力净收益 +0.07876，但延迟5分钟变为 -0.69704 | 未有真实双腿成交偏差分布前禁止影子候选晋级 |
| 历史静态币种面板 | 用今天仍活跃的币种回看历史会漏掉退市失败者 | H1 固定 8 个当前高流动性币种 | 后续全市场研究必须使用点时宇宙 |
| 研究结果可被脚本重写 | 重跑会改变时间戳、清单或结果，从而污染已登记证据 | 原下载和运行命令会覆写文件 | 本轮已改为完成后只验哈希并拒绝覆写 |
| 登记链未重放状态机 | 攻击者可重算哈希后插入非法完成顺序 | 原验证只检查链和文件哈希 | 本轮已逐事件重放状态转换 |
| 本地哈希链可整体重写 | 有文件系统权限者可连同历史一起重算 | 当前无远端、签名、保护分支或 WORM | 在进入 F0 前必须外部锚定 |

### P1：很可能系统性高估收益或低估尾部亏损

| 问题 | 影响 | 必须增加的验证 |
|---|---|---|
| 下一根 5m 开盘成交只延迟约 1 ms | 实盘信号计算、网络和下单不可能瞬时完成 | 冻结 30/60/120 秒延迟；用其后的买一/卖一或逐笔成交 |
| K 线开盘是成交价，不是可交易盘口 | 忽略买卖价差和盘口排队 | 保存 bookTicker/深度；注意 RPI 订单不在 bookTicker 中 |
| 固定滑点与名义规模无关 | 大单、低流动性和波动时冲击严重低估 | 按订单金额/ADV/盘口深度建模，无法重建时用保守容量上限 |
| 没有部分成交、拒单、断线和限频 | 回测假定每次都完整成交 | 影子盘记录请求、确认、成交与失败原因 |
| 手续费写死为 5 bps/边 | 实际 maker/taker、VIP、BNB 折扣会变化 | F0 启动时读取账户佣金并每日留存 |
| H1 手续费按固定两边扣除 | 精确费用应随入场和出场成交名义变化 | 新执行器逐腿按成交名义计算 |
| 资金费按费率近似收益 | 实际资金费使用结算时标记价格，区间也可能变化 | 使用实际事件时间、事件 mark price 和当时费率 |
| 没有合约过滤器与状态变化 | tickSize、stepSize、minNotional、停牌和退市会使订单无法执行 | 保存点时 exchangeInfo 与所有状态变化 |
| 没有稳定币换汇与抵押折价 | USDT/USDC 配对可能把汇率变化误认作价差收益 | 两腿统一计价并压力测试脱锚和抵押折价 |
| 5m OHLC 无盘中路径 | 止损、双腿同步和同 K 线成交顺序不可判定 | 决策窗口至少降到逐笔或 1 秒级；模糊时取最不利路径 |
| 无组合并发风险 | 同一冲击可同时触发多币，实际风险高度相关 | 组合风险上限、事件簇限额和相关性压力 |
| 无强平流、保险基金和 ADL 模型 | 极端行情尾部损失缺失 | 压力情景强制跳空、盘口消失和去杠杆 |

### P1：数据和统计失真

| 问题 | 影响 | 必须增加的验证 |
|---|---|---|
| ZIP 未校验 CRC 与解压后长度 | 损坏归档可能被静默接受 | 新解析器校验 CRC-32、压缩/解压长度 |
| 无效行和重复时间戳被静默丢弃/覆盖 | 数据错误不会使实验失败 | 严格失败并报告无效、重复、缺口计数 |
| K 线字段约束不完整 | 不可能的 OHLC/成交量可进入信号 | 校验 closeTime、OHLC、成交量和 taker 子集 |
| 缺口可能被滚动窗口跨越 | 缺口前后数据被当作连续历史 | 每个滚动窗口和持仓路径都检查连续性 |
| 原始数据只在本地且被 Git 忽略 | 本地丢失后难以复核 | 内容寻址备份；保留官方 URL、哈希和下载时间 |
| 官方归档可能修订 | 相同 URL 后续可能给出不同文件 | 清单锁哈希并外部存证，禁止静默替换 |
| 同时发生的多币交易被当作独立样本 | naive t 值和交易数被夸大 | 按信号时间簇聚合，做区块 bootstrap |
| 只删除最佳 5 笔 | 同一行情事件的多笔赢家仍可能集中 | 同时删除最佳 5 个事件簇 |
| 多假设反复试验没有错误率预算 | 足够多的尝试必然出现假阳性 | 保存全部失败；限制每轮假设数并报告试验总数 |
| 缺少安慰剂和反向测试 | 无法区分机制与时间段巧合 | 预登记非事件窗口、时间错位或符号置换安慰剂 |
| 固定样本内门槛不等于置信区间 | PF 通过可能只是抽样误差 | 报告依赖调整后的区间，而非只给点估计 |

### P2：运行和治理风险

- 旧项目的 `claimScan()` 是先查后写，并发任务可能重复处理同一扫描；
- 旧项目关仓写入不是单一数据库事务，失败可产生交易和持仓不一致；
- 复用旧 Gmail 依赖前需重新审计已知高风险依赖；
- 新项目尚无 CI、远端保护分支、签名提交、离线备份和灾难恢复演练；
- 登记锁在进程崩溃后可能残留，需要有审计记录的人工恢复流程；
- 当前没有生产下单端点，这是安全优点；不得因为研究迭代而提前添加。

12. 新增公开微观结构采集协议，按币安当前 `/public` 与 `/market` WebSocket 路由分离盘口、成交、强平和标记价格流；
13. H9 (`HY-EXP-0013`) 已预注册真实强平压力与盘口恢复前向验证，规则变化不得回写到H1–H8；
14. 采集烟测对外部WebSocket失败时写入 `status: failed` 和错误清单，0字节文件不得被解释为有效样本。
15. 新增前向数据验证器：在进入PnL前核对原始文件哈希、重复消息、未来时间戳、强平字段和本地盘口快照/`pu` 序列；`not_ready` 或 `invalid` 目录只能计入数据质量统计。

这些修复提高可审计性，但没有创造策略收益，也不能把本地账本升级为真正不可篡改系统。

## 6. 继续迭代的硬门槛

下一实验必须满足以下顺序：

1. 在读取新增实验数据前写明机制、唯一参数、成交时钟、成本、样本范围和淘汰条件；
2. 代码测试通过后提交 Git，并把完整 commit 写入完成包；
3. 下载后锁定每个官方文件的 URL、状态、字节数和 SHA-256；
4. 数据质量有任何无效、重复或非预期缺口即失败，不做静默修补；
5. 结果必须同时报告基准/压力/极端成本、币种/方向/半年/月、最佳 5 笔和最佳 5 事件簇剔除；
6. D0 只能决定淘汰或是否值得进入更广开发验证，不能宣布可实盘；
7. 规则一旦看过结果即冻结；修改必须新建实验 ID；
8. 真正晋级仍需 2026-07-30 边界后的独立 F0，并同时达到 180 天与 100 笔已关闭交易；
9. 未经明确批准保持 PAPER_ONLY，绝不添加真钱下单。
